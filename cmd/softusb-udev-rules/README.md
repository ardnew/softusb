# softusb-udev-rules

Command `softusb-udev-rules` generates udev rules for USB device access on Linux systems.

## Overview

When using the softusb Linux host HAL, applications need read/write access to USB device nodes (`/dev/bus/usb/`, `/dev/hidraw*`, `/dev/usb/hiddev*`). By default, these devices are only accessible to root. This tool generates udev rules that grant access to specific users or groups, eliminating the need to run applications as root.

## Installation

```bash
go install github.com/ardnew/softusb/cmd/softusb-udev-rules@latest
```

Or build from source:

```bash
cd cmd/softusb-udev-rules
go build
```

## Usage

```bash
softusb-udev-rules [flags]
```

### Flags

| Flag          | Default   | Description                                                                           |
| ------------- | --------- | ------------------------------------------------------------------------------------- |
| `-o file`     | stdout    | Output file path. Files generated with `-o` include `file`'s basename in the header.  |
| `-vid id`     |           | Filter by USB Vendor ID (hex)                                                         |
| `-pid id`     |           | Filter by USB Product ID (hex)                                                        |
| `-class id`   |           | Filter by USB interface class (hex)                                                   |
| `-user name`  |           | User to grant access. When set, the user must exist and rules include `OWNER="name"`. |
| `-group name` | `plugdev` | Group to grant access (auto-detects: `plugdev` -> `input` -> `users`)                 |
| `-mode mode`  | `0660`    | File permissions                                                                      |
| `-all`        | false     | Generate rules for all USB devices                                                    |
| `-hid`        | false     | Generate rules for all HID devices                                                    |
| `--manpage`   | false     | Print the manual page in manpage format and exit                                      |

At least one of `-all`, `-hid`, `-vid`, or `-class` must be specified unless `--manpage` is used.

Files generated with `-o FILE` start with this header:

```udev
### FILE-BASENAME
# Generated by softusb-udev-rules (https://github.com/ardnew/softusb)

```

### Manual Page

Print the manual in raw manpage format:

```bash
softusb-udev-rules --manpage
```

View the manual in a terminal:

```bash
man <( softusb-udev-rules --manpage )
```

Render the formatted manpage to stdout:

```bash
softusb-udev-rules --manpage | groff -man -Tutf8
```

Install it as a local manpage:

```bash
softusb-udev-rules --manpage | gzip -9c |
  sudo tee /usr/local/share/man/man1/softusb-udev-rules.1.gz >/dev/null
sudo mandb
man softusb-udev-rules
```

## Examples

### Specific Device for a User

Generate rules for a specific Logitech device and grant access to user `alice` and group `users`:

```bash
softusb-udev-rules -vid 046d -pid c52b -user alice -group users -o /etc/udev/rules.d/99-logitech.rules
```

Generated file `/etc/udev/rules.d/99-logitech.rules`:

```udev
### 99-logitech.rules
# Generated by softusb-udev-rules (https://github.com/ardnew/softusb)

# Allow access to VID=046d PID=c52b (USB device)
SUBSYSTEM=="usb", ATTR{idVendor}=="046d", ATTR{idProduct}=="c52b", MODE="0660", OWNER="alice", GROUP="users"
# Allow access to VID=046d PID=c52b (hidraw)
KERNEL=="hidraw*", ATTRS{idVendor}=="046d", ATTRS{idProduct}=="c52b", MODE="0660", OWNER="alice", GROUP="users"
# Allow access to VID=046d PID=c52b (hiddev)
KERNEL=="hiddev*", SUBSYSTEM=="usbmisc", ATTRS{idVendor}=="046d", ATTRS{idProduct}=="c52b", MODE="0660", OWNER="alice", GROUP="users"
```

### All HID Devices

Generate rules for all USB HID devices (keyboards, mice, joysticks):

```bash
softusb-udev-rules -hid -group users -o /etc/udev/rules.d/99-hid.rules
```

Generated file `/etc/udev/rules.d/99-hid.rules`:

```udev
### 99-hid.rules
# Generated by softusb-udev-rules (https://github.com/ardnew/softusb)

# Allow access to all USB HIDRAW devices
KERNEL=="hidraw*", ATTRS{bInterfaceClass}=="03", MODE="0660", GROUP="users"
# Allow access to all USB HIDDEV devices
KERNEL=="hiddev*", SUBSYSTEM=="usbmisc", MODE="0660", GROUP="users"
```

### Vendor-Specific Devices

Generate rules for all devices from a specific vendor:

```bash
softusb-udev-rules -vid 1234 -group users -o /etc/udev/rules.d/99-vendor-1234.rules
```

Generated file `/etc/udev/rules.d/99-vendor-1234.rules`:

```udev
### 99-vendor-1234.rules
# Generated by softusb-udev-rules (https://github.com/ardnew/softusb)

# Allow access to VID=1234 (USB device)
SUBSYSTEM=="usb", ATTR{idVendor}=="1234", MODE="0660", GROUP="users"
# Allow access to VID=1234 (hidraw)
KERNEL=="hidraw*", ATTRS{idVendor}=="1234", MODE="0660", GROUP="users"
# Allow access to VID=1234 (hiddev)
KERNEL=="hiddev*", SUBSYSTEM=="usbmisc", ATTRS{idVendor}=="1234", MODE="0660", GROUP="users"
```

### All USB Devices

Generate rules for all USB devices (use with caution):

```bash
softusb-udev-rules -all -group users -o /etc/udev/rules.d/99-usb-all.rules
```

Generated file `/etc/udev/rules.d/99-usb-all.rules`:

```udev
### 99-usb-all.rules
# Generated by softusb-udev-rules (https://github.com/ardnew/softusb)

# Allow access to all USB devices
SUBSYSTEM=="usb", MODE="0660", GROUP="users"
# Allow access to all USB HIDRAW devices
KERNEL=="hidraw*", SUBSYSTEM=="hidraw", MODE="0660", GROUP="users"
# Allow access to all USB HIDDEV devices
KERNEL=="hiddev*", SUBSYSTEM=="usbmisc", MODE="0660", GROUP="users"
```

> **Warning**: Granting access to all USB devices may have security implications. Use this option only in controlled environments.

### CDC Interface Class

Generate rules for CDC devices:

```bash
softusb-udev-rules -class 02 -group users -o /etc/udev/rules.d/99-cdc.rules
```

Generated file `/etc/udev/rules.d/99-cdc.rules`:

```udev
### 99-cdc.rules
# Generated by softusb-udev-rules (https://github.com/ardnew/softusb)

# Allow access to Class=02 (USB device)
SUBSYSTEM=="usb", ATTR{bInterfaceClass}=="02", MODE="0660", GROUP="users"
# Allow access to Class=02 (hidraw)
KERNEL=="hidraw*", ATTRS{bInterfaceClass}=="02", MODE="0660", GROUP="users"
# Allow access to Class=02 (hiddev)
KERNEL=="hiddev*", SUBSYSTEM=="usbmisc", ATTRS{bInterfaceClass}=="02", MODE="0660", GROUP="users"
```

## Applying Rules

After generating rules, reload udev and trigger a rescan:

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
```

For the rules to take effect on already-connected devices, you may need to unplug and replug them.

## Applying Rules with systemd Credentials

systemd 256 and newer can load udev rules from system credentials named `udev.rules.*`. This is useful when you want the rules managed through the systemd credential store instead of writing directly to `/etc/udev/rules.d/`.

First verify that PID 1 is systemd and the systemd version is 256 or newer:

```bash
test "$(ps -p 1 -o comm=)" = systemd
test "$(systemctl --version | awk 'NR==1 {print $2}')" -ge 256
```

If either command fails, use the direct rules-file path instead:

```bash
sudo softusb-udev-rules -hid -group users -o /etc/udev/rules.d/99-softusb.rules
sudo udevadm control --reload-rules
sudo udevadm trigger
```

Generated file `/etc/udev/rules.d/99-softusb.rules`:

```udev
### 99-softusb.rules
# Generated by softusb-udev-rules (https://github.com/ardnew/softusb)

# Allow access to all USB HIDRAW devices
KERNEL=="hidraw*", ATTRS{bInterfaceClass}=="03", MODE="0660", GROUP="users"
# Allow access to all USB HIDDEV devices
KERNEL=="hiddev*", SUBSYSTEM=="usbmisc", MODE="0660", GROUP="users"
```

On systemd 256 or newer, generate a plaintext rules file and encrypt it into the encrypted credential store. Encrypted credentials should be stored under `/etc/credstore.encrypted/`; use `/etc/credstore/` only for plaintext credentials.

```bash
softusb-udev-rules -hid -group users -o ./softusb.rules
sudo install -d -m 0700 /etc/credstore.encrypted
sudo systemd-creds encrypt --name=udev.rules.softusb - /etc/credstore.encrypted/udev.rules.softusb < ./softusb.rules
rm ./softusb.rules
```

Generated file `./softusb.rules` before encryption:

```udev
### softusb.rules
# Generated by softusb-udev-rules (https://github.com/ardnew/softusb)

# Allow access to all USB HIDRAW devices
KERNEL=="hidraw*", ATTRS{bInterfaceClass}=="03", MODE="0660", GROUP="users"
# Allow access to all USB HIDDEV devices
KERNEL=="hiddev*", SUBSYSTEM=="usbmisc", MODE="0660", GROUP="users"
```

Install a helper service that imports the encrypted credential, asks udev to load credentials, reloads rules, and triggers existing devices. `SYSTEMD_EDITOR=tee` is used so `systemctl edit --full --force` writes the service unit from stdin.

```bash
sudo env SYSTEMD_EDITOR=tee systemctl edit --full --force udev-credential-sync.service <<'EOF'
[Unit]
Description=Reload softusb udev Rules from Credentials
ConditionPathExists=/etc/credstore.encrypted/udev.rules.softusb
After=systemd-udev-load-credentials.service

[Service]
Type=oneshot
ImportCredential=udev.rules.softusb
ExecStart=/usr/bin/udevadm control --load-credentials
ExecStart=/usr/bin/udevadm control --reload-rules
ExecStartPost=/usr/bin/udevadm trigger
RemainAfterExit=yes

[Install]
WantedBy=multi-user.target
EOF
```

Then reload systemd and enable the helper. Starting the helper runs `udevadm control --load-credentials`, reloads udev rules, and triggers existing devices.

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now udev-credential-sync.service
```

After changing the encrypted credential later, run:

```bash
sudo systemctl restart udev-credential-sync.service
```

The credential name `udev.rules.softusb` is loaded by udev as `/run/udev/rules.d/softusb.rules`.

## Group Membership

Users must be members of the specified group to access devices through group permissions. The tool auto-detects the first available group from `plugdev`, `input`, `users` — or you can specify one explicitly with `-group`.

Check which group was selected in the generated rules, then add your user if needed:

```bash
sudo usermod -aG users "$USER"
```

Log out and back in for the group membership to take effect. For the current shell only, you can reload your login session without restarting the machine:

```bash
exec sudo -iu ${USER}
```

> **Note**: `plugdev` is common on Debian/Ubuntu systems. Arch-based and other distributions may not create this group — the tool falls back to `input` or `users` automatically.

If you use `-user`, the generated rules include `OWNER="name"` so that user can access matching device nodes as the file owner. You can combine `-user` and `-group` when both owner and group access are useful.

## Common USB Interface Classes

The `-class` flag filters by USB **interface** class (not device class), which correctly matches composite devices where the class is defined at the interface level.

| Class        | Hex  | Description                                        |
| ------------ | ---- | -------------------------------------------------- |
| HID          | `03` | Human Interface Device (keyboard, mouse, joystick) |
| Mass Storage | `08` | USB storage devices                                |
| CDC          | `02` | Communication Device Class (serial, modem)         |
| Audio        | `01` | Audio devices                                      |
| Video        | `0e` | Video devices (webcams)                            |
| Hub          | `09` | USB hubs                                           |

## Troubleshooting

### Permission Denied

If you still get permission errors after applying rules:

1. Check group membership: `groups "$USER"`
2. Verify the group exists on the system: `getent group users`
3. Verify the user exists when using `-user`: `id alice`
4. Verify the rules file exists: `ls -la /etc/udev/rules.d/99-*.rules`
5. Test rule matching and look for errors: `sudo udevadm test "$(udevadm info -q path -n /dev/hidraw0)"`
6. Try unplugging and replugging the device

### Rules Not Loading

Verify udev can parse the rules without errors (look for "Failed to resolve group" or similar):

```bash
sudo udevadm test /sys/bus/usb/devices/<device>
```

For systemd credentials, verify the encrypted credential exists and can be decrypted by the local system:

```bash
sudo test -f /etc/credstore.encrypted/udev.rules.softusb
sudo systemd-creds decrypt /etc/credstore.encrypted/udev.rules.softusb - >/dev/null
```

### Finding Device Information

Use `lsusb` to find VID:PID:

```bash
lsusb
# Bus 001 Device 005: ID 046d:c52b Logitech, Inc. Unifying Receiver
```

Use `udevadm` for detailed device information:

```bash
udevadm info -a -n /dev/bus/usb/001/005
```
